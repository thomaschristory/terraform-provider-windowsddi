# Windows DDI Provider

Manage Microsoft Windows Server DHCP (IPv4) and DNS with Terraform, with import support so existing servers can be adopted:

- DHCP: scopes, reservations, exclusion ranges and option values.
- DNS: primary zones (forward and reverse, file-backed or AD-integrated), conditional forwarders and record sets (A, AAAA, CNAME, PTR, MX, SRV, TXT).

The provider runs the `DhcpServer` and `DnsServer` PowerShell cmdlets on a Windows host over SSH or WinRM. Nothing is installed on the server.

## Requirements

- Windows Server 2016 or later with the DHCP Server and/or DNS Server role (or a management host with the RSAT tools, see `dhcp_server` and `dns_server`).
- OpenSSH Server (recommended) or WinRM enabled on the host.
- An account in `DHCP Administrators` to manage DHCP and in `DnsAdmins` to manage DNS.
- Terraform 1.5 or later.

## Example Usage

```terraform
terraform {
  required_providers {
    windowsddi = {
      source = "thomaschristory/windowsddi"
    }
  }
}

variable "password" {
  type      = string
  sensitive = true
}

# Connect over SSH (OpenSSH Server on Windows) directly to the server running the DHCP and DNS roles.
# The host key is checked against ~/.ssh/known_hosts unless ssh_host_key is set.
provider "windowsddi" {
  host      = "srv01.example.local"
  transport = "ssh"
  username  = "EXAMPLE\\svc-terraform"
  password  = var.password
}

# Alternatively, connect with WinRM over HTTPS using Kerberos:
#
# provider "windowsddi" {
#   host           = "srv01.example.local"
#   transport      = "winrm"
#   winrm_auth     = "kerberos"
#   kerberos_realm = "EXAMPLE.LOCAL"
#   username       = "svc-terraform"
#   password       = var.password
# }
```

## Transports

### SSH (default)

Install and start OpenSSH Server on the Windows host:

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
```

The host key is verified. Either add the host to your `known_hosts` file (`ssh-keyscan dhcp01.example.local >> ~/.ssh/known_hosts`), or pin it with `ssh_host_key`. `insecure = true` disables the check and is only meant for labs.

Password and public key authentication are supported. The default shell of the SSH server does not matter: the provider always starts `powershell.exe` itself.

### WinRM

WinRM over HTTPS (port 5986) with NTLM is the default when `transport = "winrm"`. Basic and Kerberos authentication are also available with `winrm_auth`. Kerberos uses the password of `username` and reads realm settings from `kerberos_config` (default `/etc/krb5.conf`).

When connecting to a management host and targeting another server with `dhcp_server` or `dns_server`, credentials may not be delegated (Kerberos double hop). Connecting directly to the server that runs the role avoids this.

## DHCP and DNS on different servers

One provider block talks to one host. When DNS runs on a domain controller and DHCP on another server, or each needs a different account, declare two aliased provider blocks (`alias = "dhcp"`, `alias = "dns"`), each with `host` pointing at the right server, and set `provider = windowsddi.dns` on the DNS resources.

## AD-integrated zones

AD-integrated zones replicate between domain controllers. Point the provider at one DC and keep it there: a read against another DC can briefly show drift until replication catches up.

## DHCP failover

If scopes are in a failover relationship, manage them on one partner only and let replication run, or run `Invoke-DhcpServerv4FailoverReplication` after applying.

## Environment variables

Every provider attribute can be set with an environment variable named `WINDOWSDDI_` followed by the attribute name in upper case, for example `WINDOWSDDI_HOST`, `WINDOWSDDI_PASSWORD` or `WINDOWSDDI_KERBEROS_REALM`. Values in the configuration take precedence.

## Schema

### Optional

- `dhcp_server` (String) DHCP server to manage, passed to every DHCP cmdlet as `-ComputerName`. Leave unset when `host` is the DHCP server. Can be set with the `WINDOWSDDI_DHCP_SERVER` environment variable.
- `dns_server` (String) DNS server to manage, passed to every DNS cmdlet as `-ComputerName`. Leave unset when `host` is the DNS server. Can be set with the `WINDOWSDDI_DNS_SERVER` environment variable.
- `host` (String) Hostname or IP address of the Windows host that runs the cmdlets (the DHCP or DNS server itself, or a management host). Can be set with the `WINDOWSDDI_HOST` environment variable.
- `insecure` (Boolean) Skip host verification: the SSH host key check, or TLS certificate verification for WinRM over HTTPS. Defaults to `false`. Can be set with the `WINDOWSDDI_INSECURE` environment variable.
- `kerberos_config` (String) Path to the `krb5.conf` file. Defaults to `/etc/krb5.conf`. Kerberos only. Can be set with the `WINDOWSDDI_KERBEROS_CONFIG` environment variable.
- `kerberos_realm` (String) Kerberos realm, for example `EXAMPLE.LOCAL`. Required when `winrm_auth = "kerberos"`. Can be set with the `WINDOWSDDI_KERBEROS_REALM` environment variable.
- `kerberos_spn` (String) Service principal name of the WinRM service. Defaults to `HTTP/<host>`. Kerberos only. Can be set with the `WINDOWSDDI_KERBEROS_SPN` environment variable.
- `known_hosts_file` (String) Path to an OpenSSH `known_hosts` file used to verify the host key when `ssh_host_key` is unset. Defaults to `~/.ssh/known_hosts`. SSH only. Can be set with the `WINDOWSDDI_KNOWN_HOSTS_FILE` environment variable.
- `max_concurrency` (Number) Maximum number of PowerShell commands run at the same time. Defaults to `4`. Can be set with the `WINDOWSDDI_MAX_CONCURRENCY` environment variable.
- `password` (String, Sensitive) Password for `username`. With SSH and `private_key`, it is tried as the key passphrase first. Can be set with the `WINDOWSDDI_PASSWORD` environment variable.
- `port` (Number) Port to connect to. Defaults to `22` for SSH, `5986` for WinRM over HTTPS and `5985` for WinRM over HTTP. Can be set with the `WINDOWSDDI_PORT` environment variable.
- `private_key` (String, Sensitive) PEM encoded private key for SSH public key authentication, an alternative to `password`. SSH only. Can be set with the `WINDOWSDDI_PRIVATE_KEY` environment variable.
- `ssh_host_key` (String) Expected SSH host public key in `authorized_keys` format (for example `ssh-ed25519 AAAA...`). When unset, `known_hosts_file` is used. SSH only. Can be set with the `WINDOWSDDI_SSH_HOST_KEY` environment variable.
- `transport` (String) How to reach `host`: `ssh` (default, OpenSSH Server on Windows) or `winrm`. Can be set with the `WINDOWSDDI_TRANSPORT` environment variable.
- `username` (String) Account used to connect, for example `EXAMPLE\\svc-terraform`. It must be a member of `DHCP Administrators` to manage DHCP and of `DnsAdmins` to manage DNS. Can be set with the `WINDOWSDDI_USERNAME` environment variable.
- `winrm_auth` (String) WinRM authentication: `ntlm` (default), `basic` or `kerberos`. WinRM only. Can be set with the `WINDOWSDDI_WINRM_AUTH` environment variable.
- `winrm_https` (Boolean) Use HTTPS for WinRM. Defaults to `true`. Over HTTP with NTLM, messages are encrypted with SPNEGO. WinRM only. Can be set with the `WINDOWSDDI_WINRM_HTTPS` environment variable.
